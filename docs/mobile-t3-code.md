# T3 Code 借鑒記錄（2026-11-11）

研究副本：`pingdotgg/t3code`，commit `d2c25950`。

這份文件記錄 Homing 借鑒了哪些 T3 Code 的產品模式、哪些刻意沒有搬，以及後續仍值得
做的項目。T3 Code 是 Expo / React Native；Homing Android 是 Kotlin + Compose。兩者
只共享互動原則，不共享元件或樣式。

## 已落地

### 1. 待辦貼近輸入區

T3 把等待授權／等待輸入放在會話底部、拇指可及的位置。Homing 新增
`SessionPendingDock.kt`：

- 固定在輸入框上方，不要求使用者先找回頭部的授權卡。
- 兩個以內選項直接顯示按鈕；更多選項才展開詳情。
- 等待回覆時可直接聚焦輸入框，展開後最多顯示五行事件摘要。
- 完整事件仍留在時間線，dock 不是唯一資料來源。

### 2. 會話內搜尋與跳轉

`SessionSearch.kt` 與 `SessionSearchSheet.kt` 會搜尋目前已載入的訊息、事件、工具輸出、
檔案路徑與計畫步驟：

- 搜尋結果標示角色與時間，命中詞高亮。
- 點結果會關閉搜尋並捲到原時間線位置。
- 搜尋範圍遵守「思考預設不載入」；未展開 reasoning 時不會偷偷抓取。
- 顯示上限 50 條，避免大型會話一次塞滿記憶體。

### 3. 列表整理手勢與可逆操作

`ProjectsScreen.kt` 參考 T3 的 swipe row 與 undo pattern：

- 右滑置頂／取消置頂，左滑歸檔。
- 長按仍保留完整快捷選單，手勢不是唯一入口。
- 每次操作都有 Undo Snackbar；不會要求使用者重找原列。
- 震動與 Snackbar 只在實際狀態變更後出現。

### 4. 不離開閱讀位置

會話時間線在遠離底部時顯示「回到最新」；有新內容但使用者正在讀舊段落時，改顯示
「有新內容 ↓」而不強制跳到底部。這和 T3 的 scroll-to-bottom control 是同一原則：
背景更新不能搶走閱讀位置。

### 5. 首頁先呈現需要處理的事

- 「等你處理」預設只顯示三件，其餘由使用者展開。
- 頂部不再放獨立的大型「離開模式」卡；改為頂欄月亮按鈕，狀態仍可辨識但不佔垂直空間。
- 運行中會話使用橫向膠囊列，完成項目留在較低優先級。

### 6. 排隊回覆可管理

`SessionQueuedRepliesSheet.kt` 讓使用者看到 Agent 尚未讀取的回覆：

- 逐條撤回或全部撤回。
- 「編輯」先撤回舊回覆，成功後才把文字放回輸入框，避免同一內容重複排隊。
- 只處理伺服器確認 `reply_id > 0` 且狀態為 `QUEUED` 的回覆；本地 optimistic outbox
  不會被誤撤回。

### 7. 壓縮列表頁工具列

`ProjectsScreen.kt` 把原本常駐的搜尋、Agent 篩選與三段分組控制收進按需介面：

- 搜尋按鈕展開單行搜尋框。
- Agent 篩選改成底部 sheet，使用品牌 logo 與 48 dp 點擊區。
- 「按項目／按 Agent／按時間」合成一個下拉選單。
- 摘要只保留「N 個會話 · N 運行中 · N 等你 · N Agent 篩選」。

### 8. PC 控制台按寬屏重新排版

Homing 控制台是桌面管理端，不追求手機等價。1500 px 與 1700 px 兩個斷點會：

- 把會話樹由 252 px 擴到 300／320 px，減少長標題截斷。
- 正文閱讀欄由 780 px 擴到 900／940 px，字級提升至 13.5／14.25 px。
- 資訊抽屜在 1500 px 以上提升為可讀的 10.5–12 px，不再是手機級小字。
- 1700 px 以上保留 384 px 固定資訊欄，會話、正文、詳情可以同時閱讀。
- 開始正文搜尋時自動收起右側詳情，避免搜尋欄、正文與詳情互相壓縮。

## 刻意沒有搬

- **React Native / Expo 原生元件與 Glass 效果**：Homing 用 Compose，直接照搬會得到
  另一套平台語彙；只保留資訊層級與操作位置。
- **Live Activity、Widget、App Shortcuts**：需要額外原生 extension、簽章與背景更新
  契約，不能只靠現有前端完成。
- **完整檔案樹、diff inspector、內建終端、PR 面板**：T3 有對應的 runtime file API；
  Homing 目前沒有等價的唯讀檔案契約，硬做會變成只顯示截圖或不可操作的假面板。
- **Working / Settled 雙 shelf 全量搬移**：Homing 首頁已有「等你／運行中／較早」三區，
  再疊一層 shelf 只會增加文案。若日後會話量再上升，應先做資料分頁與持久化排序，再談
  新的分組。
- **T3 的雲端 runtime / device stream**：與 Homing 的 relay、LAN 與配對模型不同，不能
  只因畫面好看就接入。

## 後續候選

1. 把連續的工具呼叫、檔案改動與 reasoning 合成單一「工作記錄」群組，預設只顯示摘要，
   展開後才列出每一步。這會比逐條卡片更接近 T3 的 work log，但需要同時處理增量 SSE、
   搜尋定位與舊資料相容。
2. 為附件上傳加入持久化佇列與斷點續傳；目前回覆本身有 outbox，附件仍以單次上傳為主。
3. 在 Android 加入 widget／Quick Settings tile，只顯示「需要你」數量與最近一個授權，
   不從 widget 直接執行破壞性操作。
4. 以唯讀契約為前提設計檔案／diff inspector；先補後端 endpoint，再決定是否做在手機端。

## 邊界

- 所有 T3 式手勢都必須保留可見按鈕作為替代入口。
- 撤回、歸檔、停止、授權等都必須由伺服器確認，不能只改本地畫面。
- 背景更新不得強制改動使用者的閱讀位置。
- 手機預設不抓 reasoning；需要時才額外請求。
