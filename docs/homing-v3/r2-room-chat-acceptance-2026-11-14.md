# 会议室群聊与行动项验收（2026-11-14）

本轮参考 [Octo Android](https://github.com/Mininglamp-OSS/octo-android) 的群聊／离线交互和 [Pachat](https://pachat.ai/zh) 的人和已有 Agent 一起讨论的体验，沿用 Homing 的 Android Compose 与 Go 会议室实现，没有导入第三方代码。R1 仍是只读、按轮发言；实体手机、公网移动数据和真实 Agent 回合继续待验收。

## 群聊与消息

- 每条发言显示成员身份与状态，用户消息显示已送达；输入区提供 `@` 选择，也识别手动输入的 Agent 标识和中文标点。每条消息最多指定一个房内可点名 Agent。
- 带 `@` 的发言和点名在后端同一持久化操作里完成；当前发言不受打断，暂停时只排队。已有尚未消费的不同点名时，后来的点名会被拒绝，原选择不被覆盖。
- 每条消息分配稳定的客户端标识。后端对同标识／同内容幂等，标识用于不同内容则返回冲突。Android 保存每房间的草稿与待确认消息，显示发送中、已送达、发送失败和结果待确认。
- 网络中断或 5xx 不自动重送；轮询发现匹配的服务端回执后才确认。用户主动清除未知状态前需确认已检查记录。会议结束后未送达草稿仍可查看、复制。清除回执与匹配草稿使用同一次同步持久化提交。

## 纪要行动项

- 识别纪要“行动项”章节中的项目符号和编号条目，作为可编辑的建议；用户选择会议中的 Agent、检查任务文字和基准提交，再明确确认派发。
- 基于确认时的 Git 提交创建独立 worktree，并保留原会议工作目录相对仓库根的子目录；未提交和未跟踪文件不会带入。若确认后的基准已改变，要求重新查看。
- 保存任务身份及准备／启动边界，重复确认不会重复启动。准备阶段中断时可验证并复用同仓库的干净工作区；状态不明的启动不会自动重放。提前到达、会话尚未绑定的完成事件可在绑定后或重启读取时按事件水位恢复。
- 房间展示任务状态、执行者、原生会话入口和返回结果。没有匹配行动项时不会自动派发；任务写入行为只在用户确认的独立 worktree 中发生。

## 验证

- Go：`go build ./...`、`go vet -tags headless ./...`、`go test -tags headless ./... -count=1 -timeout=300s` 通过；会议室新增功能 race 测试通过。
- Android：**187 项测试，零失败／错误／略过**；Compose 测试覆盖 `@` 选择、待确认消息、结束后草稿、显式确认、行动项编辑和结果显示。
- 独立 git archive 加本轮专属文件的 Go build 与 relayapi 全套测试通过；测试只用临时 Git 仓库、合成 Agent／事件，没有向用户真实会话发消息。
- 独立审查发现的点名覆盖、消息落盘和结束后草稿、准备中断、子目录与基准、启动早期完成事件、中文标点等问题均有回归覆盖。
- Android 候选 `0.11.5-dev`／versionCode `17`：`output/homing-v3-stabilization/r2/app-0.11.5-dev-17.apk`；SHA-256 `c990ea255ad8f6a4f402691f277e4650e46f22fea78aaf7948ace33ded91614a`，debug 签名与 R1 候选一致。

本轮没有手机或模拟器端到端操作证据；Compose、MockWebServer 和后端合成测试不能替代真机及真实 Agent 验收。18787 正式服务没有切换；公网上的移动网络连接和手机实机继续列为待办。
