# Homing 核心流程评估：检测 → 接入 → 装手机端 → 管理会话

2026-11-12 · 对应提交：控制台首页改为 Agent、实时流、灰鸽 v2

## 1. 核心流程走一遍（改动前）

| 步骤 | 用户要做的事 | 问题 | 严重度 |
|---|---|---|---|
| 打开控制台 | 首次被送进 3 步向导，之后首页是「总览」 | 首页不是 Agent，核心动作藏在「Agent › 已接入 / 目录与接入」两个页面里 | 高 |
| 看到本机 Agent | 向导第 1 步列出 `/api/agents` | 只列已装的，没装的看不到；勾选框和「接入」是两回事，勾了不等于接入 | 中 |
| 安装缺的 Agent | 目录页只显示一条可复制命令 | Homing 不执行命令；Codex、Claude Code 连命令都没有；WorkBuddy 没有下载入口 | 高 |
| 装手机 App | 向导第 3 步有「下载安卓版」按钮 | 按钮在电脑上打开 `/apk`，APK 下到了电脑而不是手机 | 高 |
| 配对 | 扫控制台二维码 | **控制台的二维码是 `homing://pair?v=1&host=&token=`，App 只认 `homing://pair?s=&t=&h=&fp=`，扫了报「字段不完整」**；能用的只有终端里的 `homing pair` | 阻断 |
| 配对确认 | 终端里输入 y | 四个校验词只在终端里显示，控制台看不到 | 高 |
| 设备页 | 看已配对手机 | `/api/devices` 只读旧的设备令牌，端到端配对的手机（peers.json）不显示 | 中 |
| 开始用 | 回手机 | 没有任何地方告诉用户「下一步去手机上做什么」 | 低 |

## 2. 这一轮改了什么

### 电脑端首页 = Agent（`/console/`）

- 头部四步进度：接入 Agent → 装好手机 App → 配对手机 → 在手机上管理会话，每一步实时打勾，点击跳到对应区域。
- 三组卡片：
  - **这台电脑上已安装**：一个大按钮「接入」。内置 Agent 打开推送并在支持时自动装钩子；清单类走 quick connect。
  - **已接入**：能力标签（手机可回复 / 只读 / 手机可开新会话 / 钩子是否已装 / 会话数），钩子没装时直接给「装钩子」。
  - **还没安装，可以一键装上**：Homing 核实过的十个排前面，其余 Magpie 目录的折叠在「还有 N 个」里。
- **一键安装**：点开先看官方命令（curl 安装脚本 / Homebrew / npm），这台电脑没有对应工具的选项置灰；确认后由本机执行，卡片上滚动显示输出，装完自动重新检测。
  - 安全边界：`POST /api/agent-catalog/{id}/setup` 只接受目录里的命令序号，不接受任意命令；只允许回环地址、没有云 RPC 标记、Origin 为本机的请求（手机、局域网、其它网站都拒绝），写入审计日志。
  - 桌面应用（WorkBuddy、Cursor、Zed、Warp、Windsurf、Antigravity）给官网下载页。
- 右侧固定的手机卡：一个二维码解决两件事（见下）。

### 一个二维码：装 App + 配对

- 二维码内容是 `http://<电脑局域网地址>:18787/get#p=<homing://pair…>&c=<6 位码>`。
  - 手机**系统相机**扫：打开 `/get` 落地页 → ①「下载安装包」（直接从这台电脑下 APK）→ ②「打开 Homing 配对」（`homing://pair` 深链，App 新增了 intent-filter）。
  - **App 内扫码**：`PairingInvite.parse` 会从 `/get` 链接里取出真正的配对链接，旧的 `homing://` 码照样能用。
  - 配对链接放在 URL 片段里，不会出现在任何服务器日志。
- 配对改走端到端加密的 `/api/cloud/pair/*`（与 `homing pair` 同一套）。服务没配中转时自动推导局域网 `ws://` 地址；配了官方中转就走中转。
- 手机发起后，控制台卡片上直接显示四个校验词和「一样，接受 / 不一样，拒绝」，不用再开终端。

### 实时流（`/console/flow`）

参考 Magpie 的路由视图：左边手机与电脑控制台，中间 Homing，右边已接入的 Agent，下方会议室。每一跳画成沿连线移动的彩色数据包，节点显示收发计数，下面的轨迹表可点进会话。

数据来自新的 `/api/flow`（最近 400 跳，只在内存里）与 `/api/flow/stream`（SSE）。来源：

| 跳 | 从 → 到 | 触发 |
|---|---|---|
| 事件 | Agent → Homing | hook 事件入库（完成一轮 / 请求授权 / 等你回复 / 出错） |
| 输出 | Agent → Homing | 正在被查看的会话有新输出（每会话 2 秒合并一次） |
| 推送 | Homing → 手机 | 通知真正发出（含合并条数） |
| 操作 | 手机 / 控制台 → Homing | 回复、审批、新建会话、@ 协作、停止、会议控制（来自审计点，区分局域网 / 中转） |
| 回复 | Homing → Agent | 回复送达 / 排队 / 失败 |
| 协作 | Agent → Agent，会议室 → Agent | @ 派活（提问 / 派活 / 审查 / 交接）、会议室点名发言 |
| 结果 | Agent → Agent / 手机 | 协作结果回传 |
| 会议 | Agent → 会议室，会议室 → 手机 | 发言、纪要完成 |

只记标题和不超过 90 字的预览，不存正文。

### 灰鸽 v2 动画

`pigeon_v2.json` 的八个场景现在有两个播放器（控制台 `lib/pigeon.ts`、安卓 `HomingPigeonScene.kt`），读同一份精简后的 JSON：

| 场景 | 电脑端 | 手机端 |
|---|---|---|
| 收信 recv | 侧栏：待处理数变多；首页：接入 / 安装成功；实时流：Agent → Homing | 启动页入场；顶栏：新动态变多 |
| 寄出 send | 实时流：Homing → 手机 | — |
| 轻点 tap | 点侧栏品牌标；**点托盘图标**（20 帧序列） | 点顶栏品牌标、下拉刷新、「我的」页品牌标 |
| 唤醒 wake | 控制台打开、服务恢复 | 重连成功；启动页连接行 |
| 等你处理 wait | 侧栏：有待处理时循环；首页：有手机在等确认校验词 | 顶栏：有待处理时循环 |
| 离线 sleep | 侧栏：本机服务无响应 | 顶栏：和电脑断开；启动页：正在连接 |
| 配对成功 pair | 首页手机卡：接受校验词后 | 「添加电脑」完成页 |
| 出错 error | 首页：安装失败；实时流：失败的一跳 | — |

系统开了「减少动态效果」时两端都只停在定格，颈环颜色保留状态色。

### 手机首页顶部

- 顶栏只留：鸽子（32dp）+ Homing（21sp）+ 两个 48dp 按钮（图标 24dp）。连接胶囊以前和一个 Spacer 平分剩余宽度，被压到一半并截断，现在移走。
- 新的概览卡：第一行「我的 Mac · 局域网 ……… 已连接」，下面大标题「N 件新动态」和副标题，再下面三个等宽、至少 64dp 高的数字块：待处理（点开全部待处理）/ 运行中 / 全部会话。
- 收件箱旧版（`HomingInboxScreen`）也用新顶栏：连接胶囊占满品牌名和按钮之间的空间。

## 3. 仍然不方便的地方（下一轮）

1. **APK 分发**：现在只能同一个 Wi‑Fi 从电脑下载。官方中转上线后应提供公网下载地址，`/get` 页按网络情况给出。
2. **Windows 一键安装**：目录里还没有 PowerShell 版本命令，Windows 上只能复制命令。
3. **需要登录的 Agent**：Codex、Claude Code 装好后第一次运行要登录，目前只在安装弹窗里提示；可以在卡片上加「在终端里登录」按钮（打开终端并执行 `codex login` / `claude`）。
4. **设备页**：端到端配对的手机还不在「设备」页里，需要合并 peers.json 的列表，并支持撤销。
5. **手机端「下一步」引导**：配好后手机首页可加一张一次性的引导卡（回复、审批、@ 协作、会议室各一句）。
6. **实时流**：目前只有本进程内存；想回看历史需要落盘或从审计日志 + 事件库重建。节点超过 9 个 Agent 时只显示前 9 个。
7. **简繁混用**：控制台与安卓还有零星繁体文案（如部分旧注释和提示），按「简体为主、英文第二」的决定继续统一，并抽出字符串资源做英文。
8. **截图回归**：首页顶部这类比例问题需要截图测试兜底（Roborazzi），这一轮只加了尺寸断言（数字块 ≥ 48dp）。
