# 會議室 R1 驗收（2026-11-13）

本批完成 R1 程式碼、控制台入口與 Android 點名操作，並以隔離的合成 Agent 完成兩端流程驗收。手機目前無法連線，使用者已同意先推進其他工作；本批 Android 操作證據來自 API 35 模擬器，不能替代 R1 實機複驗。公網行動數據依使用者決定繼續保留待辦。

## 交付行為

| 項目 | 實際行為 |
|---|---|
| 控制台入口 | 導航「會議室」→ `/console/rooms`；列表、建房、參會角色、討論記錄、原生會話入口與紀要 |
| Android 點名 | 從房內可選參會者中指定下一位；顯示待執行選擇；暫停時點名不會自行恢復 |
| 排程規則 | 每位參會者每輪至多一次；點名只調整下一個未完成輪次的剩餘順序；不打斷當前發言，不增加回合；當前／失敗／已發言目標回明確錯誤 |
| 暫停與恢復 | 當前發言完成後停住；恢復沿用原子會話與已保存的回合，避免重複落盤 |
| 結束與紀要 | 收尾後禁止插話、加輪與再次點名；最終一份紀要保留結論、各方觀點、分歧及行動項 |
| 重啟恢復 | 進行／整理中的房間落盤為暫停；保存 active_turn 的 Agent、輪次、類型、派發 ID、基線和投遞階段；恢復只回收或等待原派發結果 |
| 不確定投遞 | 已越過 submitting 邊界時絕不自動重送；找不到派發、啟動尚未綁定會話或舊資料無投遞邊界時暫停提示，可結束並匯總已有記錄 |
| 紀要恢復 | 兩端對暫停且已請求結束的房間顯示「繼續整理紀要」，仍禁止插話與新增回合 |
| 寫盤失敗 | 控制操作回 500，記憶體不報成功；回合／紀要保存失敗即暫停，不安排下一次原生操作；建房失敗不留下幽靈房間 |
| UI 邊界 | Android 控制列窄屏換行；兩端保留失敗草稿、阻擋重複操作並排除舊輪詢結果；控制台離頁停止輪詢，內容以文字安全呈現 |

## 兩端操作證據

控制台使用 1440×1000 及 390×844 視窗；Android 使用獨立 Pixel 7／API 35 模擬器及實際 Debug APK。測試服務在獨立資料目錄的 18820，Vite 5174；只註冊兩個受控合成 Agent，無任何真實 Agent 程序或使用者會話被呼叫。

1. 控制台建房完成兩人兩輪、暫停、點名、插話、恢復、四次發言及一份紀要；HTML 測試文字保持文字，窄屏無水平溢出，離頁不再輪詢 rooms。
2. Android 建立另一場兩人兩輪會議；暫停時點名 Claude，當前 Codex 完成後仍保持暫停；按繼續才由 Claude 接續。控制台同步顯示選擇與狀態。
3. Android 實際鍵盤輸入並送出合成發言，控制台收到相同文字；最後一輪按「結束並出紀要」，當前發言完成後才整理紀要。
4. 整理紀要期間重啟**測試服務**；兩端自動重連並顯示暫停，均有「繼續整理紀要」。由 Android 恢復後完成，API 確認四個唯一發言槽位及恰好一筆紀要。
5. Android 顯示紀要全部四章與雙方觀點，結束後沒有發言輸入區；控制台紀要一致。重連後觀察期間瀏覽器錯誤與警告均為零；停服務期間的網路失敗有保留，不算成程式例外。

本機外部 QA 目錄位置記在 `.superpowers/sdd/2026-11-13-homing-stabilization/r1-qa-directory.txt`，內含兩端截圖、UI tree、瀏覽器操作記錄及 `r1-result.json`。Web 證據維持在倉庫外，不進版控。
